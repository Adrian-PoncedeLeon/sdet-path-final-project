
# Project Instructions

## 1. Project Objective
Build a maintainable, reliable, and professional test automation framework from scratch.

Required deliverables:
- 5 UI automated tests
- 5 API automated tests
- 3 Mobile automated tests
- Design Patterns
- Test reporting
- BDD with Cucumber
- GitHub Actions execution

The framework should prioritize maintainability, modularity, reusability, and reliability.

## 2. Technology Constraints
- Use only technologies, tools, libraries, and frameworks covered by the course or explicitly authorized by the user.
- Do not introduce alternative technologies or substitute existing tools without approval.
- Do not add dependencies without prior approval.
- Before proposing a dependency, explain its purpose and the course module or requirement it supports.
- Do not make major architectural or technology decisions without user approval.

## 3. Development Workflow
- Work in small, clearly defined tasks.
- Complete and verify the current task before moving to the next one.
- Never advance automatically to another task.
- Preserve existing project work and avoid unnecessary changes.
- Prefer simple, maintainable solutions over unnecessary complexity.

## 4. Approval Requirements
Before every individual action:
1. Briefly explain what will be done and why.
2. Identify relevant files or commands.
3. Wait for explicit user approval.

Explicit approval is required before:
- Creating, modifying, or deleting files.
- Executing terminal commands.
- Installing or updating dependencies.
- Running tests or other commands.
- Creating branches or commits.
- Pushing changes to GitHub.
- Creating repositories, pull requests, or other remote resources.

Approval for one action does not authorize subsequent actions.

## 5. Code Quality
- Follow established best practices for the selected technologies.
- Keep code modular, readable, reusable, and maintainable.
- Avoid duplication and unnecessary abstractions.
- Use appropriate error handling.
- Avoid hardcoded credentials, secrets, and sensitive configuration.
- Use configuration files and environment variables where appropriate.
- Do not introduce unnecessary dependencies or complexity.

## 6. Reporting and Verification
After completing each task:
- Summarize what was implemented.
- Identify files created or modified.
- Report commands and tests executed.
- Provide actual verification results.
- Clearly identify errors, limitations, or unresolved issues.
- Do not claim success without verification.

## 7. Git and GitHub
- Explain relevant Git operations before executing them.
- Never commit, push, merge, or publish without explicit approval.
- Preserve existing changes.
- Do not overwrite or delete files without authorization.

## 8. AI-Assisted Development
- Review AI-generated code for correctness and consistency.
- Validate implementation through appropriate tests or checks.
- Identify assumptions and potential risks.
- Do not treat generated code as correct without verification.

## 9. Communication
- Keep explanations concise and focused on relevant technical decisions.
- Explain architectural choices, dependencies, trade-offs, and important implementation details.
- Do not explain trivial code line by line unless requested.
- Ask for clarification when a requirement is ambiguous or a decision requires user input.
- Do not assume authorization from silence.
